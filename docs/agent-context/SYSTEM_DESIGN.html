02The four pillars

① Rebrand

One scripted, rebasable white-label patch: names, icons, bundle IDs, update feed, telemetry. Done when: dev app shows forkbase identity.

② First-class Linux

AUR + Flatpak/deb + AppImage; /proc-based metrics replacing macos-process-metrics; Wayland/Hyprland: tray, notifications, clipboard, deep links. Done when: clean install on a fresh Arch box, author dogfoods daily. Priority track (D9).

③ Free Android

Enable the in-repo Expo app on Android; upstream is iOS-only + Pro-gated. Done when: APK installs, phone reviews agents against your own cloud.

④ Self-host cloud

Docker compose for api/gate/relay/realtime/review-host/usercontent; local accounts; Pro checks gone. Done when: desktop remote access works over LAN with zero upstream cloud.

06Fork discipline — binding rules (D7)

1 · Seams, not edits

New code lives in packages/forkbase-* and plugin mechanisms — never inline-edit upstream where a config seam works.

2 · One rebrand patch

All white-label edits live in a single scripted, rebasable patch — never scattered.

3 · Conscious hard-fork moment

Track upstream until beta is stable; then pick a divergence commit and own it. No drift.

4 · Generic fixes go upstream

Linux fixes upstream will accept become PRs to superset-sh/superset. Every merge shrinks our diff.

Cadence: weekly upstream sync (merge upstream main → run suite → rebase rebrand patch → merge to forkbase main).
